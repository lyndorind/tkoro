# Contributing Guidelines

Thank you for your interest in contributing to this project.

## 1. Types of Contributions

We welcome:
- Bug reports
- Feature suggestions
- Documentation improvements
- Code improvements
- Test improvements

## 2. Reporting Issues

Before creating a new issue, check whether a similar issue already exists.

Use the appropriate issue template and provide a clear description.

## 3. Development Workflow

1. Clone the repository.
2. Create a new branch from main.
3. Make the required changes.
4. Test the changes locally.
5. Commit your changes with a meaningful message.
6. Push the branch to GitHub.
7. Open a Pull Request.

## 4. Branch Naming

Use descriptive branch names:

- feature/feature-name
- fix/bug-name
- docs/documentation-name

## 5. Commit Requirements

All commits must be signed.

Use concise and meaningful commit messages.

Example:

docs: update installation instructions

## 6. Local Checks

Install project dependencies:

uv sync

Run code checks:

uv run ruff check .

## 7. Pull Requests

Each Pull Request should:
- Describe the changes.
- Reference related issues when applicable.
- Follow the Pull Request template.
- Pass the required checks.
- Be reviewed before merging.

## 8. Code of Conduct

All contributors must follow the Code of Conduct.
